# Agent Architecture

## 1. Overview

Every AI agent in this Proof of Concept follows the same runtime architecture.

Instead of hardcoded business logic, each agent follows a reasoning loop:

```text
Goal

↓

Load Context

↓

Load Memory

↓

Reason (Llama)

↓

Create Plan

↓

Select Tool

↓

Execute Action

↓

Update Memory

↓

Respond
```

Each agent is autonomous within its assigned responsibility.

The Project Manager Agent acts as the orchestrator, while the remaining agents are specialists.

# 17. Design Principles

- Every agent has a single responsibility.
- All reasoning is performed by Llama.
- PostgreSQL stores transactional state.
- pgvector stores semantic knowledge.
- The PM Agent is the only orchestrator.
- The Client Agent is the only agent exposed to the client.
- Specialist agents never communicate directly with the client.
- Agent outputs are persisted before being passed to the next stage.
- Agents remain stateless between requests except for the persisted memory they retrieve.

# 19. Summary

The agent architecture follows a lightweight autonomous model suitable for a PoC:

- A common runtime for every agent
- Llama-based reasoning
- PostgreSQL for persistent state
- pgvector for semantic retrieval
- PM Agent as the central orchestrator
- Client Agent as the conversational interface
- Specialist agents focused on a single domain

This design keeps the implementation modular, easy to extend, and achievable within the one-week development timeline while clearly demonstrating autonomous multi-agent collaboration.
