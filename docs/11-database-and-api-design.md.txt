# Database and API Design

## 1. Overview

This document defines the data storage and API structure required for the Cross-Network Autonomous Agent-to-Agent Communication PoC.

The objective is to keep the implementation simple while supporting:

- User authentication
- Project management
- Agent memory
- A2A communication
- Message tracking
- Proposal lifecycle

The PoC uses separate databases for each organization.

          Client Organization


          Client Database

# 3. Client Database Design

## 3.1 Users Table

Stores client authentication information.

Example:

```json
{
 "id":1,

 "name":"John",

 "email":"john@test.com",

 "password_hash":"xxx"
}
3.2 Projects Table

Stores project requests.

Fields:

Field	Description
id	Project ID
user_id	Client user
name	Project name
description	Business description
status	Current status
created_at	Creation time

Example:

{
 "name":
 "Healthcare Platform",

 "status":
 "SUBMITTED"
}
3.3 Requirements Table

Stores structured requirements.

Fields:

Field	Description
project_id	Related project
requirement_text	Original input
summary	AI summary
missing_information	Missing details
3.4 Conversations Table

Stores clarification discussions.

Example:

{
 "project_id":
 "project-101",

 "sender":
 "client-agent",

 "message":
 "Expected number of users?"
}
3.5 Proposal Table

Stores received proposals.

Fields:

Field	Description
project_id	Project reference
architecture	Solution design
cost	Estimated cost
timeline	Duration
status	Review status

6. A2A Gateway APIs

The gateway exposes communication endpoints.

6.1 Agent Registration
Endpoint
POST /a2a/register

Purpose:

Register an agent.

Request:

{
 "agent_id":
 "technical-agent",

 "organization":
 "SoftwareCompany",

 "capabilities":
 [
  "architecture"
 ]
}
6.2 Send Message
Endpoint
POST /a2a/message

Purpose:

Send agent messages.

Request:

{
 "message_type":
 "TASK_REQUEST",

 "sender":
 "pm-agent",

 "receiver":
 "technical-agent",

 "payload":
 {}
}
6.3 Message Status
Endpoint
GET /a2a/message/{id}

Returns:

{
 "status":
 "DELIVERED"
}
7. Client Backend APIs
Authentication
POST /auth/login

POST /auth/logout

Projects

Create project:

POST /projects


Get projects:

GET /projects

Requirements

Submit requirement:

POST /projects/{id}/submit

Proposal

View proposal:

GET /projects/{id}/proposal


Approve proposal:

POST /projects/{id}/approve

8. Company Backend APIs
Incoming Requests
GET /company/projects

Start Analysis
POST /company/projects/{id}/analyze

Agent Results
GET /company/projects/{id}/results

Proposal Management

Generate:

POST /company/projects/{id}/proposal


Approve:

POST /company/projects/{id}/send

9. Agent Internal APIs

Every agent exposes:

Process Message
POST /agent/process


Example:

{
 "message_type":
 "TASK_REQUEST",

 "task":
 "ANALYZE_REQUIREMENTS"
}
Memory

Store:

POST /agent/memory/store


Retrieve:

GET /agent/memory
