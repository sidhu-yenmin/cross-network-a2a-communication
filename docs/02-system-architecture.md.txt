# System Architecture

## 1. Overview

The system consists of two completely independent networks that communicate only through an Agent-to-Agent (A2A) Gateway.

The client never communicates directly with the company network.

Instead, every interaction passes through the Client Agent, making the conversation appear as a single chatbot while autonomous agents collaborate behind the scenes.

# 3. Network Separation

The architecture intentionally separates both organizations.

## Client Network

Responsible for

- User Authentication
- Project Creation
- Requirement Form
- Client Chat
- Client Agent
- Project Memory

The Client Network never accesses Company Agents directly.

---

## Company Network

Responsible for

- Requirement Analysis
- Planning
- Cost Estimation
- Technical Analysis
- Timeline
- Risk Analysis
- Proposal Generation

The Company Network never communicates directly with the client.

---

## Gateway

Acts as the secure bridge.

Responsibilities

- Authenticate requests
- Validate JWT
- Route requests
- Route responses
- Log communications
- Prevent direct access between networks

The Gateway contains no business logic.

# 6. Shared Infrastructure

Both networks use the same logical components.

## PostgreSQL

Stores

- Projects
- Requirements
- Chat Sessions
- Chat Messages
- Tasks
- Agent Memory
- Proposal
- Approvals

Transactional data never goes into pgvector.

---

## pgvector

Stores only semantic knowledge.

Examples

- Requirement summaries
- Project summaries
- Architecture decisions
- Proposal summaries
- Client preferences

Avoid storing every chat message.

---

## Llama

Used by every agent.

Responsibilities

- Requirement analysis
- Reasoning
- Planning
- Tool selection
- Summarization
- Proposal generation

The Llama model never stores memory itself.

All memory is retrieved from PostgreSQL and pgvector before prompting.

# 11. Design Principles

This architecture follows several principles.

### Independent Networks

Client and Company networks remain isolated.

---

### Chat-First Experience

The user interacts only with a conversational interface.

---

### Autonomous Collaboration

Agents communicate without human coordination.

---

### Simple PoC

Avoid enterprise complexity.

- No Kubernetes
- No Message Brokers
- No Event Streaming
- No Microservices

---

### Persistent Memory

Transactional data is stored in PostgreSQL.

Semantic knowledge is stored in pgvector.

---

### Stateless Gateway

The Gateway performs only

- Authentication
- Validation
- Routing
- Logging

No reasoning or business logic exists inside the Gateway.

---

# 12. Architecture Summary

The chatbot-based A2A architecture provides:

- Two independent organizational networks
- Two chatbot conversations
- Autonomous agent collaboration
- Central PM orchestration
- PostgreSQL for transactional persistence
- pgvector for semantic retrieval
- Llama for reasoning and planning
- Secure communication through a stateless A2A Gateway

This architecture is intentionally lightweight, making it suitable for a Proof of Concept while still demonstrating realistic multi-agent collaboration.
